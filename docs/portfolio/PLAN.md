# WPS Portfolio — Implementation Plan

**Status:** draft for review · 2026-09-28 · branch `claude/charming-cray-kbbz0k`
**Companion documents:** `EXECUTION-MODEL.md` (how the Epic, issues, models and the executor session work), `prototype-behaviour.md` (implementation-grade behaviour reference), `handoff/` (the design bundle: spec README, prototype HTML, screenshots, brand assets).

## How this plan was produced

1. The design handoff bundle was read in full and distilled into `prototype-behaviour.md` (data model, every derived rule, exact copy, 35 README-vs-prototype discrepancies with the reading adopted).
2. The existing repository was inventoried for reusable tokens, components, backend patterns, build/serve constraints, test conventions and security rules.
3. Three independent architecture proposals were written under different lenses (isolation-first, reuse-first, unattended-delivery-first), scored by two adversarial judges (risk-and-isolation lens; delivery-and-verifiability lens), and synthesised into the plan below. Both judges ranked the isolation-first "sidecar" proposal highest (82/100 each); the best ideas from the other two are grafted in and marked **[B]** / **[C]**.

## Non-negotiables carried into every task

- The existing AI Reports app in this repository and the live "AI Dashboard v1" are untouchable: no edits under `Wps.Watch.AiReporting*`, no root solution/`.gitignore`/`wwwroot` edits, no writes to v1 (its MCP write tools are never called; two read tools are called once, by the orchestrator, for the one-time import).
- Every task is sized for one subagent, owns a disjoint set of paths, and is proven by automated checks (unit tests, Playwright end-to-end against a seeded local database, typecheck, lint, build) before it is committed and pushed.
- Every phase ends in something the reviewer can run with one command and click through against the handoff screenshots.

## 1. Architecture decision

**Chosen: the sidecar.** WPS Portfolio is its own ASP.NET Core 8 host + its own Vite/React 18/TypeScript client + its own read-write EF Core database, all under one new folder `portfolio/` with its own solution file. Nothing under `Wps.Watch.AiReporting*` changes; the root `dotnet build` still resolves only `Wps.Watch.AiReporting.sln`; the v1 dashboard is read once (list/get only) and never written.

**Why not the alternatives.** Co-hosting inside the AI Reports service (Plan B) edits the untouchable `Program.cs`/csproj/`.sln`/appsettings, ships EF Sqlite natives in the legacy artefact even with the flag off, shares an assembly with `WithToolsFromAssembly()` and an injectable replica context (a real write path), and cannot go live without adding real JWT auth to the legacy host. Plan C's sidecar is sound but adds four projects to the legacy `.sln` (team's `dotnet test` now runs Portfolio), gates on pixel baselines that differ between this container and CI runners, and builds Jira/GitHub sync jobs before the feed framework exists. Both plans contributed ideas that are grafted below.

### 1.2 Routes, ports, serving

- API prefix `/api/portfolio/*`; public feed `/public/portfolio-feed.json`; `/health`, `/health/ready`. Vite `build.assetsDir = "portfolio-assets"` and `base` configurable, so a future path-based proxy in front of both apps cannot collide with `/api/reports|ask|discovery` or `/assets/*`.
- Kestrel http `5180` / https `7280` (legacy 5077/7202); Vite dev `5183` proxying `/api`, `/public`, `/health` → `http://localhost:5180` (legacy 5173). HTTPS redirection off in Development, so Playwright/curl need no cert.
- Client routes: `/sign-in`, `/portfolio`, `/ai`, `/ai/:vendor`, `/ask`, `/settings`, `/settings/feeds/:feedId`; `MapFallbackToFile("index.html")` on this host only.
- `dotnet run --project portfolio/Wps.Watch.Portfolio -- up --seed sample [--reset]` = migrate → seed when empty/reset → build the client if `wwwroot/index.html` is missing (`npm ci && npm run build`, skippable with `--no-client`) → listen. `dotnet build`/`dotnet test` never invoke npm (fix from review: the MSBuild target only runs on `dotnet publish` or `-p:BuildClient=true`).

### 1.3 Persistence

- Own database, never the wpsWatch replica, never v1. `Portfolio:Db:Provider = Sqlite | SqlServer`.
- Dev/tests/CI/e2e: SQLite (`Microsoft.EntityFrameworkCore.Sqlite`), file `portfolio/.data/portfolio.<Env>.db` (WAL; ignored by the nested `.gitignore` — the root one does **not** ignore `.db`). Integration tests: `DataSource=:memory:` on a held-open connection per test (safe under `Parallelize(MethodLevel)`). e2e: `portfolio.e2e.db` recreated by Playwright's `webServer` command.
- Production: a **new** Azure SQL database (`wps-portfolio`, its own principal with `db_datawriter`; a second `db_datareader` principal for Ask), Entra auth via `Azure.Identity`. Added in Phase 5 with `Migrations/SqlServer` generated through an `IDesignTimeDbContextFactory`; verified in CI on an `mssql/server:2022` service container (`ProviderParityTests`).
- Migrations: one folder per provider; `MigrateOnStartup` true in Development only; production runs `dotnet Wps.Watch.Portfolio.dll migrate` as a release step. Rule: one task per phase may add a migration.
- Schema: Projects (Title, Owner, Type, Designation, Step, Approved, Started, NextRelease, IsPublic, Description, CurrentStatus, NextStep, AutoStatus, IsDraft, V1Slug?, ImportedLinksJson?), ProjectLinks, Tasks (ParentTaskId for sub-tasks, Source Manual|Jira, JiraKey, Start, Days, Chain, SortOrder, DeletedUtc for undo), TaskLinks, RepoEntries (unique Pattern per project), People, Departments (unique Name), VendorPricing, JiraProjectLinks (Unlink clears ProjectId, keeps the row — §5.17), WardenRules, AskSettings, AlertSettings/Recipients/Acks, FeedConfigs, FeedCredentials (Data-Protection ciphertext + Mask + Meta), FeedRuns, GitHubRepos, GitHubIssues/SubIssues, CommitBatches, WorkSummaries, AiUsageRecords, AppState (DataProfile, PublicFeedToken), ImportAudit. DateOnly for dates, decimal(18,4) money, UTC timestamps. **At Risk is never stored**: `ProjectRules.IsAtRisk(project, today)` is the single implementation used by list, CSV, public-feed preview and Ask; in SQL it is computed in the Ask wrapper query with a bound `@today`, not in a view (views take no parameters — fix from review).
- Seed profiles (exclusive per DB; `--reset` to switch; refused on SqlServer without `--force`): `sample` = faithful transcription of the prototype dataset (**12** projects: 11 in the Open view + SpeciesNet Complete; 12 people; 6 departments; 3 pricing rows; 4 Jira links; 3 warden rules; **10** feeds incl. Copilot and WPS Agents with 6 runs each; 23 org repos, `wps.watch.*` → 15; alert recipients 2, threshold 3, includeDegraded false) with `Portfolio:Clock:FixedUtcNow=2026-09-23T12:00:00Z` honoured only in Development/Test so the UI reproduces the screenshots; `v1` = the read-only import of the real projects (38 non-archived verified; archived count confirmed at capture, never hard-coded).

### 1.4 Auth

- `Portfolio:Auth:Mode = Dev | WpsJwt`, fail-closed like the existing app: `Dev` outside Development throws at startup (tested).
- Dev (Phases 0–4): `POST /api/portfolio/auth/dev-login {role, name, email}` sets the session cookie; the sign-in card's gold button calls it (a small role select appears only in Dev/sample mode). `X-Portfolio-Dev-Role: Admin|Viewer|none` per request is honoured only in Development; Playwright runs three projects (`admin`, `viewer`, `signed-out`) via `extraHTTPHeaders` **[B]**.
- WpsJwt (Phase 5): validates wpsWatch HS256 tokens (key/issuer/audience from Key Vault via config), maps `"System Admin"` → Admin, `"Viewer"` → Viewer, every other role → 403 page. The browser never holds the JWT: HttpOnly/Secure/SameSite=Lax cookie `wps_portfolio_session` (Data Protection, sliding, long-lived per the copy), unsafe methods require `X-Requested-With: portfolio`.
- Policies: `Portfolio.Read` (Admin|Viewer), `Portfolio.Write`, `Settings.Read` (both; credentials omitted), `Settings.Write`, `Feeds.Admin`, `Ai.ReadAll` vs `Ai.ReadOwn` (rows filtered to the session email; unknown email → zero rows). `RouteMatrixTests` enumerates every mapped action via ApiExplorer and fails when a route is missing from the Admin/Viewer/anonymous expectation table **[C]**, so no endpoint ships without an explicit policy.
- Role parity with the legacy app is asserted by a **source-text test** that reads `Wps.Watch.AiReporting/Authorization/Roles.cs` and checks the two literals — no ProjectReference to the legacy web project (fix from review).

### 1.5 Feature flags and config (`Portfolio:*`, surfaced by `GET /api/portfolio/meta`)

`Features:InlineRowEditing` (true), `TaskRowLayout` (Ledger|TwoLine), `PillHover` (Tooltip|Swap), `AggregateStyle` (Sentence|Bar), `TaskCap` (50), `PublicFeed:Enabled`, `Feeds:SchedulerEnabled` (false in Development/tests), `Feeds:<id>:Provider = Sample|Real`, `Ask:Engine = Keyword|Claude`, `Ask:FreeSql` (Admin-only rung), `Dev:SimulateSaveFailures` / `Dev:SimulateSyncFailure` (Development only, also per request via `X-Portfolio-Simulate`), `TimeZone` (America/Denver), `Clock:FixedUtcNow` (Development/Test only). `meta` also returns `today`, `dataProfile` (`sample` shows the SAMPLE DATA tag and strip; `v1`/`live` hide them) and the feature values. All four open product decisions ship as flags with every variant implemented and e2e-tested; a Development-only `?features=` query override lets one Playwright spec cover each variant.

### 1.6 Non-interference — enforced, not promised

1. **Build**: separate `.sln`; no ProjectReference from any Portfolio project to `Wps.Watch.AiReporting*` (runtime or test); nested `Directory.Build.props`/`.gitignore` cannot leak upward; the root `.sln`, root `.gitignore`, csproj files and `wwwroot` are untouched.
2. **Runtime**: separate process, ports, config root (`Portfolio__*`), user-secrets id (`wps-watch-portfolio`), HttpClient names, Anthropic key (D5), database. No `[McpServerToolType]` in the legacy assembly (Portfolio's optional MCP is a separate executable).
3. **`portfolio/scripts/check-isolation.sh`** (run before every push, and in CI): (a) `git rev-parse HEAD:<dir>` for `Wps.Watch.AiReporting`, `Wps.Watch.AiReporting.Data`, `Wps.Watch.AiReporting.Test` and `Wps.Watch.AiReporting/wwwroot` must equal the tree hashes recorded in `portfolio/isolation-baseline.json` — history-free, so it works in shallow clones; (b) when `origin/main` is present, `git diff --name-only $(merge-base)..HEAD` must be a subset of the allowlist `portfolio/**`, `.github/workflows/portfolio.yml`, `.claude/hooks/session-start.sh`, `.claude/settings.json`, `docs/portfolio/**`, `README.md` (exactly one appended line) — `.claude/settings.json` and `docs/portfolio/**` are already in today's diff, which the original script would have failed on; (c) staged-content grep for full key shapes (`ghp_[A-Za-z0-9]{36}`, `github_pat_[A-Za-z0-9_]{22,}`, `sk-ant-[A-Za-z0-9_-]{20,}`, `sk-proj-[A-Za-z0-9_-]{20,}`, `ATATT3[A-Za-z0-9_=-]{20,}`, `-----BEGIN [A-Z ]*PRIVATE KEY`), which do not trip on the fixture masks (`ghp_…4c9e`, `ATATT…c3e8`).
4. **CI canary**: `dotnet build` + `dotnet test Wps.Watch.AiReporting.sln` unchanged (64 pass / 2 inconclusive offline) and a runtime canary **[B]**: start the legacy host with a dummy `ConnectionStrings__WpsReplica`, byte-compare `GET /` with the committed `wwwroot/index.html`, assert `/health` 200 and `/api/portfolio/meta` 404 there.
5. **v1**: no repository code can reach v1; only the orchestrating Claude calls `list_portfolio_projects` / `get_portfolio_project` once, after I2 approval; the rule is written into `portfolio/docs/decisions.md` and every subagent prompt.
6. **Decommission**: `git rm -r portfolio .github/workflows/portfolio.yml`, revert two hook hunks and one README line; rehearsed on a scratch branch in P5-6.

### 1.7 Integrations, Ask, and the ideas grafted in

- **Feeds** (`Integrations`): `IFeedProvider.RunAsync(FeedRunContext) → FeedRunResult{OK|Partial|Failed, Records, Message}`; the only DB write path from feeds is `IFeedSink`. Ten feed ids: `claude, chatgpt-cost, chatgpt-usage, codex, gemini, github-commits, github-issues, jira, copilot, wps-agents`. Sample providers reproduce the screenshot health table (ChatGPT usage Failed 401 ×13, Codex Partial, Copilot expired, WPS Agents late). A **slim feed core lands in Phase 2 before GitHub Issues/Jira consume it [B]** (contracts, registry, runner, `FeedRuns`, `FeedHealth.Evaluate`, run-now); scheduler, credential store and alerts follow in Phase 4. Hosted services never throw: every tick and run is wrapped, and an integration test injects a throwing provider and asserts `/health` stays 200 **[B]**. Health labels are **OK / Degraded / Failed / Paused** (§5.8). The alert threshold is evaluated (consecutive Failed ≥ threshold), not inert (§5.16).
- **Ask** (`PortfolioAskService`, own code, same shape as `ChatService`): `IAskEngine` with `KeywordAskEngine` (the prototype's three routes; used when no key) and `ClaudeAskEngine` (Messages API tool loop, model + standing instructions from AskSettings, ≤ 6 iterations). Tools are **typed, role-scoped queries over EF** (`list_projects`, `projects_releasing`, `ai_spend`, `feed_health`, `settings_lookup`) whose `ToQueryString()` feeds the **Show SQL / Hide SQL** toggle **[B]**; a guarded free-form `run_sql` over `vw_ask_*` views on a read-only connection is an Admin-only rung behind `Ask:FreeSql`. The transparency block is always built from real execution. Viewers never see feed/settings tools and get the spec's refusal copy. Every ask is audit-logged (user, question, sql, rows, ms), never the answer text to the DB.
- **Work Summary**: `IWorkSummaryGenerator` → `SampleWorkSummaryGenerator` / `ClaudeWorkSummaryGenerator` (own key `Portfolio:Anthropic`, model ids resolved via the `claude-api` skill into one config table mapping the three UI labels).
- **Shared rule fixtures [C]**: `Data/Seed/rules/*.json` (at-risk boundaries, sum-row cases, filter/sort cases, chain scheduling + roll-up, auto-step, link normalisation, CSV golden bytes) drive MSTest and are copied into `client/src/test/fixtures` by `npm run sync-fixtures` with a checksum test, so the C# and TS mirrors cannot drift.
- **Tokens drift test [B]**: a vitest reads the legacy `ClientApp/src/styles.css` `:root` block read-only and fails if a shared token in `tokens.css` diverges.
- **Behaviour-doc §5 readings adopted [C]**: 7-column AI table with Total (§5.1), 260px popover (§5.2), current step filled (§5.3), approval floor 2 (§5.4), scheme-only link fallback (§5.6), Warden JSON validated on add (§5.18), undo = re-insertion at the original index (§5.20), Unlink keeps the Jira row (§5.17), fields block gains Step and Start Date editors (§5.29), duplicates prevented server-side (§5.28), floating Ask hidden on `/ask` (§5.24), `.csv` names (§5.26), guard set `= + - @ \t \r` (§5.27).

## 5. Unattended operating procedure

### 5.1 Dispatch

- One subagent per task row; the prompt is generated from a template: task id/title/description, owned paths, the allowlist and the two absolute rules ("never edit anything under `Wps.Watch.AiReporting*`, the root `.sln`/`.gitignore`; never call a v1 MCP tool"), the behaviour-doc sections and README lines to implement, exact acceptance criteria and check commands, the `api-contract.md` excerpt, and the definition of done. Subagents read `docs/portfolio/handoff/` and `prototype-behaviour.md` from the repo, never from the scratchpad.
- Concurrency: at most two subagents at once, chosen so `files_or_areas` are disjoint and `par` is true for both. A .NET-heavy and a client-heavy task share the working tree; two .NET-heavy tasks run in separate `git worktree`s under the scratchpad (npm deps only installed there when the task needs them) and are integrated by the orchestrator with `git cherry-pick` onto the branch head after their gates pass. Every subagent starts from a clean, up-to-date tree (`git status` clean, `git pull --ff-only`).
- Ownership: shared files (`Program.cs`, `router.tsx`, `api/index.ts`, `PortfolioDbContext`, migrations, `RouteMatrixTests` table) are edited only by the task that owns them in that phase; another task that needs a change returns an "integration note" in its result, which the orchestrator applies in the owning task or a 15-minute integration mini-task. One migration per task, sequential.
- Integration order follows `deps`; inside a phase, server tasks precede their client consumers, and a parallel client task codes against `api-contract.md` types plus the dev-harness fixtures, with its e2e enabled at integration time.

### 5.2 QA gate every task passes before commit

1. `dotnet build portfolio/Wps.Watch.Portfolio.sln -warnaserror` and `dotnet test portfolio/Wps.Watch.Portfolio.sln` (full suite; `RouteMatrixTests` fails on any route without an expectation row).
2. In `client/`: `npm run lint && npm run typecheck && npm run test && npm run build` (includes the fixture checksum and tokens-drift tests).
3. `npm run e2e -- <task specs> chrome.spec.ts smoke.spec.ts` (three role projects; retries 1, trace on retry; timing logic is unit-tested so e2e proves wiring only); the full e2e suite runs at integration and in every acceptance pack.
4. Screens the task touched: `npm run screenshots -- --only <screen>` then `node scripts/handoff-compare.mjs` produces a side-by-side PNG; the orchestrator **views the contact sheet** and rejects gross layout/colour regressions; structural Playwright assertions (text, counts, computed colours) are the gate.
5. Adversarial review: a second subagent runs the `code-review` skill at high effort over the task's diff with the acceptance criteria and the security rules (no secrets logged/echoed, policies on every action, guard/rollback on Ask SQL, no legacy edits) as the rubric; any CONFIRMED correctness or security finding is fixed by the implementer; at most two rounds, then the task is parked (5.4).
6. `portfolio/scripts/check-isolation.sh` (tree hashes, allowlist, secret grep).
7. Commit: `git add -- <owned paths>`; message `portfolio(<area>): <what>` + the session attribution lines; `git push` immediately (sessions are ephemeral). No commit ever includes `wwwroot/`, `.data/`, `test-results/` or a `.db`.

### 5.3 Cadence and deliverable notes

- Every green task = one commit, pushed at once; a one-line entry is appended to `portfolio/docs/worklog.md` (task id, what shipped, checks run, integration notes).
- Phase end (the acceptance-pack task): full suite on a fresh `--reset` DB, regenerated screenshots + contact sheets, `portfolio/docs/phases/phase-N.md` (the exact command, a click-through script mirroring "User sees", known gaps, decisions still open, the import report link from Phase 2), `git tag portfolio-phase-N` pushed, the single draft PR `claude/charming-cray-kbbz0k → main` created/updated through the github MCP with the phase summary, CI status linked. CI additionally uploads `portfolio-site.zip` (built client) and the Playwright report per phase tag.
- The user's review loop per phase is: pull, run the one command, follow `phase-N.md`, leave findings as a list; the orchestrator turns each finding into a fix task with the same gate.

### 5.4 When blocked

- A product ambiguity: apply the default recorded in `decisions.md` (the §5 readings and D8), note it in the phase report; never wait.
- A missing credential or decision (I3–I13): implement the sample/fixture path, mark the real path "ready — needs I-n" in the runbook, continue.
- A check that will not pass after two attempts plus one review round: `git restore`/`git clean` the task's owned paths, record the failure and hypothesis in `portfolio/docs/blocked.md`, dispatch independent tasks, and retry the parked task with a fresh subagent once its dependencies have moved on.
- A change that appears to require touching the legacy tree, the root solution, or a v1 write tool: stop that task, log it, and raise it to the user in the phase report; duplication inside `portfolio/` is the sanctioned alternative to sharing.
- Only I1 and I2 stop work; everything else degrades to sample mode. The orchestrator asks the user only for I-items and for phase acceptance.

## 6. Risks and mitigations

| Risk | Mitigation |
|---|---|
| A subagent "helpfully" edits `styles.css`, `Roles.cs`, `Program.cs` or the root `.sln` | Absolute rule in every prompt; tree-hash + allowlist guard before every push and in CI; legacy build/test/runtime canary; sanctioned duplication (roles, CSV guard, tokens) with parity tests |
| Accidental writes to v1 through its MCP | No repository code can reach v1; only the orchestrator calls the two read tools once (after I2); rule in `decisions.md`; the committed snapshot means re-imports never touch v1 |
| Isolation script fails on day one (existing diff, fixture masks) or in shallow clones | `.claude/settings.json` and `docs/portfolio/**` allowlisted; tree hashes recorded in `isolation-baseline.json` need no history; secret patterns anchored to full key shapes |
| Spec drift across ~55 tasks | `prototype-behaviour.md` + README are the only cited sources; acceptance quotes exact copy/values; shared JSON rule fixtures on both sides; copy-audit spec from Phase 2; screenshots reviewed by the orchestrator each phase |
| e2e flakiness (drag, 8 s undo, 1.6 s fade, polling) | Deterministic seed + fixed server clock; `page.mouse` step drags plus the keyboard reorder path; timing logic unit-tested; retries 1 with trace; no pixel gating |
| Playwright browser download blocked / version drift | `@playwright/test` pinned 1.56.1 = chromium-1194; `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`; a test asserts the pin; hosted CI installs normally |
| Parallel subagents collide (shared files, obj/ dirs, migrations) | Explicit ownership, one migration per task, worktrees for concurrent .NET tasks, rebase-before-start, full suite at integration |
| SQLite vs SQL Server drift (dates, collation, decimals, views) | Explicit converters; per-provider migrations and Ask views; `ProviderParityTests` on mssql in CI from Phase 5; no provider-specific SQL in queries |
| Vendor APIs differ from assumptions; no credentials to verify now | Sample providers first; recorded-fixture tests document assumed shapes; Partial/Failed outcomes surface on the health page; `feed-smoke` verbs and `live-smoke.sh` for the user; spec's "fields to be confirmed" copy retained |
| v1 prose export parses lossily | Golden tests on real captures, mandatory `unparsed[]` review, per-project import report, idempotent upsert by slug so corrections re-apply |
| Secrets leak into commits or responses | Credentials only via env or the Rotate UI into the Data-Protected store; nested `.gitignore` for `.env`/`appsettings.Local.json`/`.data/`; staged-content grep; a test scans every route's responses for stored credential values; e2e network assertion on Rotate |
| Data Protection keys lost on redeploy → stored credentials unreadable | Key ring persisted to the DB (Key Vault in prod, documented); startup warning when ephemeral |
| Unattended Anthropic spend | No key in dev/CI by default (keyword engine, sample summaries); separate key/workspace (D5); iteration and token caps; audit log per call |
| Ephemeral sessions lose work | One pushed commit per green task; phase tags; the SessionStart hook rebuilds the toolchain so any session resumes from the branch |
| Reviewer cannot build the client (no Node) | Node 22 listed as a prerequisite; `acceptance.ps1` checks it; CI publishes `portfolio-site.zip` per phase tag to drop into `wwwroot/` |
