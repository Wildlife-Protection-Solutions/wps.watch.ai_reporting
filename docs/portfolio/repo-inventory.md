## B. Reusable React patterns (`ClientApp/src`)

**`components/autofilter.jsx`** exports `ColumnFilterMenu, applyColumnFilters, formatFilterValue, uniqueValuesWithCounts`.
- `ColumnFilterMenu({ col, allRows, currentSet, onApply, onClear, onClose, onSort, buttonRect })`. `col = {key,label,num,w?,hint?}`; `allRows` must already be filtered by every *other* column (Excel semantics; caller uses `applyColumnFilters(rows, filters, exceptKey)`); `currentSet: Set<rawValue>|undefined`; `onApply(Set)`, `onClear()`, `onSort("asc"|"desc")`, `onClose()`; `buttonRect` = DOMRect of the trigger. Renders `position:fixed`, width 260, centred under the button, clamped to viewport (12px margins, `top ≤ innerHeight-360`). Options = `uniqueValuesWithCounts` (Map keyed by raw value; numbers asc, strings `localeCompare`). Local `selected` state initialised to `currentSet` or all values; search matches `formatFilterValue`; "Select all" toggles only visible options (indeterminate via ref); OK → `onClear()` if every option selected else `onApply(selected)`; closes on document `mousedown` outside and `Escape` (not on scroll). Labels "Cancel"/"OK"; "Clear filter" only when `currentSet.size>0`. Sort labels switch on `col.num` (matches spec).
- `applyColumnFilters(rows, columnFilters, exceptKey)` keeps rows where `allowed.has(r[key])`; an empty Set yields zero rows (usable as the spec's select-none sentinel, but the menu re-initialises an empty set to "all").
- Host wiring lives in `report.jsx` `SortHeader`: single `openFilterKey` in page state, `rect` refreshed on capture-phase scroll/resize, `ReactDOM.createPortal(..., document.body)`, `isFiltered` derived, sort tri-state asc→desc→none on the label (matches spec), `COLUMNS = [{key,label,num,w,hint}]`.
- Generalising needed: (1) remove the hard-coded `col.key === "onlinePct"` percent format in `formatFilterValue` → per-column `display(row)`; (2) spec filters on *displayed strings*, not raw values; (3) close on scroll-outside; (4) footer = "Clear filter & sort" + gold "Done"; (5) popover width = header-cell width; (6) state shape per table id `{filters:{col:{text,selected[]}}, sort}`; (7) fluid `grid-template-columns` tracks, drag-to-resize handles and the sum row do not exist anywhere — new work; (8) it is untyped `.jsx` (`checkJs:false`) — port to `.tsx`.

**`components/chat.jsx`** (`ChatPanel({onClose})`): messages `{role:'user'|'assistant', text, answer?}`; `send()` builds `history` from prior text turns, calls `ask(question, history)` from `api.ts` (`POST /api/ask`, body `{question, history:[{role,text}]}`), pushes `{text, answer}`; errors: `ask()` throws `AskError{code,status}` from the `{error,message}` body, UI special-cases `chat_not_configured`. `AnswerBlock({answer, expanded, onToggleSql, onCsv})` renders the transparency block: chips `count rows` (+`+` if `truncated`) and `window`; `filters[]` as mono `.ai-answer__filter` chips; evidence `<table>` from `columns × rows` (server sends first 8) with "+ n more rows"; actions "Show/Hide SQL" (`<pre class="ai-answer__sql">`) and CSV; `formatCell` (null→"—", numbers `toLocaleString`). Also suggestion chips, Enter-to-send textarea, typing dots, auto-scroll. Maps directly onto the Ask page's QUESTION/ANSWER/DATA card but needs: full-page layout (max-width 900) instead of a 360px rail, clickable evidence rows (deep links), "source" text, amber "No written answer" box, Viewer feed-restriction message.

**CSV helper (client):** `downloadCsv(answer)` in chat.jsx — RFC-4180 quoting only when needed, BOM (literal U+FEFF in source), fixed filename. Lacks the formula-injection prefix and quote-every-cell the spec requires → write a shared `csv.ts` mirroring server `CsvExporter` and unit-test it.

**`api.ts`:** bare same-origin `fetch`, no auth header/base URL; `runReport(id, params)` → `ReportRunResponse{reportId, executedAtUtc, durationMs, columns[], rowCount, rows[], parametersApplied}`; exported types `AskAnswer{count,window,filters,columns,rows,sql,truncated,moreCount}`, `AskResponseBody{text, answer|null}`. `useReportData.ts` shows the cancelled-flag fetch-hook pattern. `icons.jsx` `Icon({name,size,stroke})` with 36 names (search, chevron-*, arrow-up-down, filter, x, download, star, star-fill, calendar, share, more, alert, alert-circle, check, check-circle, wifi, wifi-off, camera, users, globe, map, report, sparkles, chat, sun, user, save, settings, refresh, trend-up, trend-down, circle, code). `chrome.jsx` hard-codes wpsWatch nav labels and a dead "Switch to legacy" link. `tweaks-panel.jsx` `useTweaks` posts to `window.parent` (`__edit_mode_set_keys`) and reads `localStorage['deck-stage.railVisible']` — prototype-host coupling, do not reuse. `data.js` has `fmt/fmtPct/sum/aggregate`.

## C. Backend reuse

**`Chat/ChatService.cs`** (sealed, scoped; ctor: `IHttpClientFactory` named client `"anthropic"` 120s, `DiscoveryQueryRunner`, `IOptions<AnthropicOptions>`, `ILogger`). Flow: guards `Enabled` → `ApiKey` → question; schema text cached once per process (`SemaphoreSlim`) from `_runner.DescribeSchemaAsync()` (INFORMATION_SCHEMA, `dbo`, sensitive tables/columns removed) formatted `Table(col type, ...)`; `BuildSystemPrompt(schema)` is a wpsWatch-fleet-specific string (includes the "online = seen within 1440 min" rule, "server already scopes to your orgs"); messages = history turns + question; loop ≤ `MaxToolIterations` (6): `POST {BaseUrl}/v1/messages`, headers `x-api-key`, `anthropic-version: 2023-06-01`, body `{model, max_tokens, thinking:{type:"adaptive"}, system:[{type:"text", text, cache_control:{type:"ephemeral"}}], tools, messages}`; assistant content echoed back verbatim; on `stop_reason=="tool_use"`: tool `run_sql{sql}` → `DiscoveryQueryRunner.RunQueryAsync` → `RenderRunResult` (JSON `{rowCount,truncated,rowsShown≤40,columns,rows}` or `is_error` text); tool `submit_answer{summary,time_window,filters[]}` is terminal; `end_turn` without submit → model text used as summary. **AskAnswer is built from the last successful `DiscoveryQueryOutcome.Success`, never from model claims:** `Count=RowCount`, `Window=draft.Window||"Current snapshot"`, `Filters=draft`, `Columns`, `Rows=first 8`, `Sql=ExecutedSql`, `Truncated`, `MoreCount=RowCount-8`. Outcomes: `AskResult.Success|NotConfigured|UpstreamError|NoAnswer`.
- To point it at a Portfolio store: it is hard-wired to the concrete `DiscoveryQueryRunner` (→ `WpsReplicaDbContext`, SQL Server, T-SQL `SqlGuard`). Needed: an `IAskQueryBackend { DescribeSchemaAsync; RunQueryAsync }` abstraction, a parameterised system prompt/tool descriptions, configurable `RowsToClient/RowsToModel`, schema-cache invalidation, and role scoping (Viewer: own AI rows, no Settings). Because the class is sealed with private statics, the practical route is copy-and-adapt into the new project, extracting the Anthropic request/JSON helpers into a shared internal client; refactoring `ChatService` itself is possible but touches the existing surface.

**`Discovery/DiscoveryQueryRunner.cs`:** gate order `Options.Enabled` → `user==null` (Unauthenticated) → `user.Can(ReportOperations.DiscoveryQuery)` (SystemAdmin only) → `SqlGuard.Validate` → raw ADO.NET on `_db.Database.GetDbConnection()`, ReadCommitted transaction always rolled back, `CommandTimeout`, sensitive-column strip, `MaxRows` cap → `Success(Columns, Rows as IReadOnlyDictionary<string,object?>, RowCount, Truncated, Duration, ExecutedSql)`; every run logged with user/SQL/row count. `SqlGuard` is textual (SELECT/WITH only, no `;`, keyword denylist incl. INTO/EXEC/WAITFOR, `sp_/xp_`), `SensitiveColumnFragments` (token, secret, password, apikey, securitystamp, concurrencystamp, webhook), `SensitiveTables`.

**`Discovery/CsvExporter.cs`:** `public static string ToCsv(IReadOnlyList<string> columns, IReadOnlyList<IReadOnlyDictionary<string,object?>> rows)`; apostrophe-prefix on `= + - @ \t \r`, RFC-4180 quoting only when needed (spec wants every cell quoted — minor variance), InvariantCulture, ISO dates; BOM is added by `DiscoveryController.CsvFile` (`Encoding.UTF8.GetPreamble()`), returned via `File(bytes,"text/csv",name)`. Directly reusable.

**Auth flow:** `Program.cs` pipeline `UseHttpsRedirection → UseDefaultFiles → UseStaticFiles → UseMiddleware<DevAuthMiddleware> → UseAuthorization → MapControllers → MapFallbackToFile("index.html")`. No authentication scheme, no `[Authorize]` anywhere; `UseAuthorization()` is inert. `DevAuthMiddleware` sets `UserContext{UserId, IsSystemAdmin, OrganizationIds, RoleNames}` from `DevAuthOptions` when `Enabled` and accessor empty; `UserContextAccessor` is `internal sealed`, scoped, throws on second `Set`. `UserContext.Can(op)`: SystemAdmin bypass, else role ∈ `ReportOperations.RolesByOperation[op]` — `AdminReport`(none), `UserReport`(OrgAdmin, IncidentManager, Viewer, GpsViewer), `DiscoveryQuery`(none). `Roles` constants: `"System Admin"`, `"Org Admin"`, `"Incident Manager"`, `"Viewer"`, `"GPS Viewer"`, `"Volunteer"`, `"Photo Uploader"`, `"Photo Tagger"`. Startup guard `AssertDevAuthSafeForEnvironment` throws if `DevAuth.Enabled` outside Development (also in MCP mode; `DOTNET_ENVIRONMENT` defaulted to `ASPNETCORE_ENVIRONMENT` or Development). Default dev user is SystemAdmin with empty roles; a Viewer run needs `DevAuth__IsSystemAdmin=false DevAuth__RoleNames__0=Viewer` (env vars, since `appsettings.Development.json` is gitignored). Portfolio needs its own operations (`PortfolioRead`: Viewer+Admin; `PortfolioAdmin`: SystemAdmin) — `Can()` only consults `ReportOperations`, so either add entries (additive) or provide a Portfolio-side `Can`.

**Controllers:** `[ApiController][Route("api/x")]`, inject the runner/service, `return outcome switch { Success s => Ok(anon), NotFound => NotFound(new{error="report_not_found"}), Forbidden => StatusCode(403,new{error="forbidden"}), InvalidParameters/Rejected/Failed => BadRequest(new{error,reason|errors}), Unauthenticated => Unauthorized(), Disabled/NotConfigured => StatusCode(503,new{error="..."}), UpstreamError => 502, NoAnswer => 500, _ => StatusCode(500) }`; error bodies are `{error:"snake_code", message|reason}` (client reads `body.error`/`body.message`). `HealthController` at `/health` and `/health/db`.

**DI/config conventions:** Options classes are `sealed` with `public const string SectionName` and defaults; bound via `services.Configure<T>(config.GetSection(T.SectionName))`, consumed as `IOptions<T>.Value` in ctors. Sections: `ConnectionStrings:WpsReplica` (required, throws if missing), `DevAuth`, `Discovery{Enabled,MaxRows,CommandTimeoutSeconds}`, `Anthropic{ApiKey,Model,BaseUrl,MaxTokens,MaxToolIterations,Enabled}`, `Logging`. Secrets via user-secrets (`UserSecretsId wps-watch-ai-reporting`) or `Anthropic__ApiKey` env. Lifetimes: `IReportDefinition`/`IReportCatalog` singleton, `ReportRunner`/`DiscoveryQueryRunner`/`ChatService` scoped, `DbContext` scoped (`UseSqlServer`, `CommandTimeout(15)`, `EnableRetryOnFailure(3)`, `NoTracking`). `ConfigureCommonServices(services, config, isMcpMode)` is shared by web and MCP hosts; MCP mode uses `WithToolsFromAssembly()` — every `[McpServerToolType]` in the web assembly is auto-exposed. Reports pattern: `IReportDefinition{Id,Name,Description,Operation,Parameters,ExpectedCostClass,RunAsync(db,user,params,ct)}` returning `ReportResult(ReportId, ExecutedAtUtc, Columns, Rows, ParametersApplied)` via `ReportResults.From<TRow>()` (reflection over DTO props) — the "columns-and-rows record" the spec cites.

## D. Build/serve constraints and coexistence

- `vite.config.ts`: `build.outDir: "../wwwroot"`, **`emptyOutDir: true`** — every old-client build wipes `Wps.Watch.AiReporting/wwwroot/`. **wwwroot is committed** (`index.html`, `assets/index-D7yitMZi.js`, `assets/index-GccNxi-1.css`; `.gitignore` has `#wwwroot/` commented out). A second client must never emit into that folder, and rebuilding the old client churns hashed filenames in git. Dev server :5173 proxies `/api` → `https://localhost:7202` (`secure:false`).
- `Program.cs`: `UseHttpsRedirection()`; static files served from wwwroot only, *before* DevAuth (SPA unauthenticated); `MapFallbackToFile("index.html")` swallows every non-file, non-API path (so `/portfolio/*` on the old host today returns the AI Reports SPA with 200). Swagger only in Development. Launch profiles: `http` :5077, `https` :7202+:5077, IIS Express 6192/44311, `launchUrl: swagger`. Nothing in MSBuild runs npm (no SpaRoot/SpaProxy).
- csproj: `Content/None/Compile Remove="ClientApp\**"` only; any other folder added under the web project (e.g. a second client) would be globbed as Content including `node_modules`. `InternalsVisibleTo Wps.Watch.AiReporting.Test`. `.sln` lists exactly the three projects; the session-start hook restores only `Wps.Watch.AiReporting.sln` and runs `npm ci` for every `*/ClientApp/package.json` at depth ≤ 3.
- **Coexistence options:** (1) **Recommended — separate web project `Wps.Watch.Portfolio/`** (own `Program.cs`, own `appsettings.json`, own ports e.g. 5177/7302, own `ClientApp/` → own `wwwroot/`), plus a new class library (e.g. `Wps.Watch.Shared/`) holding copies/moves of `Roles`, `UserContext`, `IUserContextAccessor`, `CsvExporter`, an Anthropic client, added to the `.sln`; zero runtime interference and no edits to the existing csproj/Program. Referencing the existing web project directly is possible but drags in its startup and `internal` types. (2) Same host, second SPA at `/portfolio`: `UseStaticFiles(new StaticFileOptions{FileProvider=…, RequestPath="/portfolio"})` + `MapFallbackToFile("/portfolio/{*path:nonfile}", …)` + Vite `base:"/portfolio/"` with a non-wwwroot outDir — additive edits to `Program.cs` but shares process, WpsReplica startup dependency, DevAuth and the MCP assembly scan. (3) Vite dev server on :5174 proxying `/api/portfolio` — dev only.
- Writable store: Portfolio needs CRUD (projects, tasks, links, repo entries, settings, feed runs); `WpsReplicaDbContext` is read-only and v1 is untouchable → own DB. Container has `docker` and `psql` but no `sqlcmd`/`sqlite3` binaries; SQL Server is not running. SQLite via `Microsoft.EntityFrameworkCore.Sqlite` (nuget.org reachable; not yet in `~/.nuget/packages`) is the cheapest seeded-local-DB path for e2e, with a provider switch to Azure SQL for deployment. For Playwright, run the API with `ASPNETCORE_URLS=http://127.0.0.1:<port>` (HTTPS redirection is skipped when no https endpoint is bound; the dev cert exists but is untrusted).

## E. Test conventions (`Wps.Watch.AiReporting.Test`)

MSTest 3.6.4 + `Microsoft.NET.Test.Sdk` 17.12, `<Using Include="Microsoft.VisualStudio.TestTools.UnitTesting"/>`, `LangVersion latest`, nullable on. `MSTestSettings.cs`: `[assembly: Parallelize(Scope = ExecutionScope.MethodLevel)]` → tests must not share mutable static state or a single DB file. Files `<Subject>Tests.cs`, namespace `Wps.Watch.AiReporting.Test`, `[TestClass]` (some `sealed`), `[TestMethod]`, `[DataRow]` for tables, `[ExpectedException]`. No `WebApplicationFactory`, no in-memory provider, `ChatService` untested (HttpClient not faked). No client tests or lint; `npm run typecheck` covers only `api.ts`, `useReportData.ts`, `main.tsx`. Playwright 1.56.1 is installed globally with Chromium in `/opt/pw-browsers` (`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` exported by the hook) — the new client should pin `@playwright/test@1.56.1`. Run with `dotnet test` at repo root.

## F. Security/hosting rules the new app must respect (README, brief v4, requirements v6, `perspectives/security.md`)

- **Auth model:** "same wpsWatch login, same roles" (brief v4). wpsWatch issues HS256 JWTs with a symmetric `JwtKey`/`JwtIssuer` from its `WpsConfiguration` section (issuer == audience); the decided approach is local validation with the shared key from Key Vault (FR-05, S-MUST-05: expired/malformed/wrong-issuer → 401), RS256/Entra as later posture. Until wired, the DevAuth shim is allowed **only in Development** and must be fail-closed at startup (S-R1-01) — Portfolio needs the same guard. Only SystemAdmin, OrgAdmin, IncidentManager, Viewer, GpsViewer may access; Volunteer/PhotoUploader/PhotoTagger get 403 on everything but `/health` (S-MUST-06/07), with automated role-by-role tests (S-MUST-30/31). Portfolio mapping: Admin = `Roles.SystemAdmin`, Viewer = `Roles.Viewer`; Viewers: read-only Settings, own AI rows, Settings hidden from Ask.
- **Secrets:** nothing secret in `appsettings.json`; user-secrets/env vars locally, Key Vault + managed identity (`DefaultAzureCredential`) in deployment; `appsettings.{Env}.json`, `*.local.json`, `.env` are gitignored; Anthropic key server-side only; spec says feed credentials are "stored server-side and never shown again".
- **Data rules:** wpsWatch data is read-only (NoTracking, SELECT-only guard, rolled-back tx; `ApplicationIntent=ReadOnly` + `ai_reports_reader` principal at Rung 2); credential/secret columns never surfaced (S-MUST-28 also lists `Email`, `PhoneNumber` — never project wpsWatch `User`/AspNet tables; Portfolio People emails live in Portfolio's own store); GPS stripped at Rung 2; every query audit-logged with user/SQL/row count (S-R1-04) but no secrets logged; LLM output rendered as plain text/sanitized markdown, never raw HTML (S-MUST-22); CSV formula-injection guard (S-MUST-23); DB content given to the LLM wrapped in untrusted-data markers (S-MUST-24); no tool call triggered solely by prior tool output (S-MUST-25); 15s statement timeout, row caps (5,000 discovery / 10,000 chat), 60 req/min rate limit at Rung 3.
- **Isolation/hosting:** separate process from the wpsWatch API, no outbound calls to it in production (S-MUST-01); same-origin SPA, no CORS; deploy target is an Azure sibling of `wps.watch.functions.scheduledreporting` sharing Key Vault (FR-V2-01), config via `appsettings.Production.json`/env vars and `DOTNET_ENVIRONMENT`; no Dockerfile or CI in repo. AI Dashboard v1 is read-only for us: its MCP exposes `create/update` tools that automation must never call.

## G. Gotchas

1. `emptyOutDir:true` + committed `wwwroot` (D above): never point a second Vite build there; avoid rebuilding the old client in Portfolio commits.
2. Root `.gitignore` swallows whole folder names: `[Ll]og/`, `[Ll]ogs/`, `publish/`, `artifacts/`, `**/[Pp]ackages/*` (a `packages/` monorepo dir would vanish), `[Rr]elease/`, `[Dd]ebug/`, `x64/`, `Backup*/`, `*.[Cc]ache`, `test-results/` (Playwright default output; `playwright-report/` is *not* ignored), `*.log`, `*.mdf/*.ldf` (but `.db` SQLite files are **not** ignored — a seeded DB would get committed), `appsettings.Development.json`. `ClientApp/.gitignore` is folder-local, so a new client needs its own (`node_modules/ dist/ .vite/ test-results/ playwright-report/`).
3. Session-start hook only finds `*/ClientApp/package.json` at depth ≤ 3 and restores only `Wps.Watch.AiReporting.sln` → name the new client folder `ClientApp` directly under the new project and add new projects to that `.sln`, or the ephemeral container will not restore them.
4. `MapFallbackToFile("index.html")` makes any Portfolio URL on the old host return the AI Reports SPA (200), masking mistakes.
5. `WithToolsFromAssembly()` — any `[McpServerToolType]` added to the existing web assembly silently changes the existing MCP server's tool list. Keep Portfolio tools in a separate assembly/host.
6. Startup hard-requires `ConnectionStrings:WpsReplica` and uses `Authentication=Active Directory Default` (`Azure.Identity`); in this container the API starts but DB calls fail slowly (credential probing), `/health/db` → 503, smoke tests → Inconclusive. Portfolio e2e must not depend on that context.
7. `UserContextAccessor` and `ReportCatalog` are `internal`; a separate project cannot use them without editing the old csproj's `InternalsVisibleTo` — copy into a shared library instead.
